چه چیزی انجام شده

انجام‌شده روی برنچ‌های feature (هنوز روی master مرج نشده‌اند مگر خودتان مرج کرده باشید) feature/bdmp-logical-css-properties، feature/dm-logical-css-properties، feature/iap-logical-css-properties
  • تبدیل استایل‌های physical مثل margin-left / left / float: left به logical مثل margin-inline-start / inset-inline-start.
  • ادغام بلوک‌های تکراری RTL/LTR در SCSS وقتی فقط آینه هم بودند.
  • در IAP: کاهش شاخه‌زنی websiteDirection در HTML/TS (سرچ‌باکس، فلش pane، صفحه‌بندی، دکمه‌های پروفایل، اسلایدر عکس).
  • اسکیل قابل استفاده مجدد: @css-logical-properties-bidi

چرا هنوز «همه‌جا» درست نیست؟

ماژول‌هایی مثل IAP و BDMP بخشی از UI را خودشان استایل می‌کنند، ولی خیلی از فاصله‌ها، مودال‌ها، گریدها و کنترل‌های مشترک از پکیج‌های بالاتر (مخصوصاً base) می‌آیند. اگر آنجا هنوز margin-left یا text-align: right باشد، در حالت LTR همان صفحهٔ «مهاجرت‌شده» هم می‌تواند کج به نظر برسد.

علاوه بر CSS، بعضی کتابخانه‌های third-party (Kendo، Fotorama، jQuery Confirm) جهت را جداگانه می‌فهمند یا اصلاً physical هستند؛ این‌ها را نباید مثل SCSS اپلیکیشن فله‌ای عوض کرد.

اولویت ۱ WebUI/base — شِل مشترک

اثر: تقریباً همهٔ ماژول‌ها این لایه را لود می‌کنند. بدون درست شدن base، مهاجرت bdmp/dm/iap ناقص می‌ماند.

حجم تقریبی اسکن: حدود ۳۳ فایل SCSS و نزدیک ۲۸۰ رخداد physical (بدون شمارش استایل‌های jquery/kendo داخل assets).

چه چیزهایی داخل base مهم‌اند؟

مسیر / ناحیه چرا مهم است
base/styles.scss استایل سراسری، تراز متن body، بلوک‌های زیاد [direction=rtl] / ltr، هدر و لایه‌های عمومی.
base/styles/gridComponent.scss و کپی assets رفتار جدول/گرید و جهت؛ ارتباط نزدیک با Kendo و کلاس k-rtl.
base/styles/ngzorro-custom-styles.scss بازنویسی ظاهر Ant Design / ng-zorro با سمت‌های فیزیکی.
base/src/lib/app/* کامپوننت‌های مشترک: modal، dropdown، toolbar، tree، search-input، accordion، multiselect، dialog، form-field و …

کارهایی که باید انجام شود

  • تبدیل physical → logical با همان قواعد اسکیل (داخل بلوک RTL نگاشت را معکوس کن، بعد بلوک‌های یکسان را ادغام کن).
  • تفاوت واقعی را نگه دار: فونت فارسی در RTL در برابر فونت لاتین در LTR.
  • تم Kendo داخل assets را فله‌ای ادیت نکن؛ مطمئن شو جایی که لازم است k-rtl ست می‌شود.
  • بعد از اتمام: تست شِل (هدر، منو، مودال عمومی، یک گرید نمونه) در هر دو dir.
پیشنهاد اجرایی یک برنچ جدا مثل feature/base-logical-css-properties بسازید و فقط WebUI/base را اسکوپ کنید. در صورت نیاز تکه‌های خیلی وابستهٔ termeh را همان‌جا یا بلافاصله بعدش انجام دهید.

اولویت ۲ WebUI/ams — حجم بالا

اثر: محصول AMS صفحات سازمان/سیستم زیادی دارد؛ استایل‌های فیزیکی و حتی direction: rtl سخت‌کد زیاد دیده می‌شود. در LTR احتمال شکستگی UI بالاست.

حجم تقریبی اسکن: حدود ۳۳ فایل SCSS و نزدیک ۷۴۰+ رخداد — بزرگ‌ترین تکهٔ باقی‌مانده از نظر تعداد رخداد.

نقاط داغ

  • فایل‌های *.external.scss زیر organization و system (groups، roles، data-sheet، services، SSO، dimensions، …).
  • قوانین تکراری که صفحه را همیشه به RTL هل می‌دهند؛ برای LTR باید یا logical شوند یا به dir سند وابسته شوند، نه hardcode.

نکتهٔ اجرایی

به‌خاطر حجم، بهتر است AMS را در چند PR خرد کنید (مثلاً organization جدا از system)، ولی همه تحت اسکیل یکسان و اسکوپ مشخص.

اختیاری داخل IAP — بعد از مهاجرت اصلی

Fotorama و attachments

کامپوننت custom-attachments هنوز جهت را به API لایبرری Fotorama می‌دهد و ایندکس تصاویر را برای RTL جابه‌جا می‌کند. این لزوماً باگ نیست، ولی یعنی منطق جهت هنوز در TS است.

  • اول در LTR واقعی رفتار گالری پیوست را تست کنید.
  • اگر درست بود، دست نزنید.
  • اگر غلط بود: تنظیمات Fotorama / آداپتر ایندکس را اصلاح کنید؛ CSS minified فله‌ای عوض نکنید.

Vendorهای minified

دارایی کجا سیاست

ترتیب پیشنهادی اجرا

  2. ams (ترجیحاً چند PR خرد)
  3. dap سپس dia-plugins / dia-objects / dia-shared
  4. authentication و بقیهٔ کوچک‌ها
  5. صحت‌سنجی share-components / table / code-editor
  6. فقط اگر باگ LTR ثابت شد: override دور vendor (نه ادیت .min.css)

چطور به AI بدهی انجام دهد؟

اسکیل Cursor به نام css-logical-properties-bidi نوشته شده تا همین migration را تکرار کند. در چت Agent بنویسید @css-logical-properties-bidi تا دستورالعمل لود شود، بعد اسکوپ را بگویید.

نمونه پیام
@css-logical-properties-bidi
روی WebUI/base مهاجرت logical CSS و bidirectional را انجام بده.
برنچ feature/base-logical-css-properties بساز، کامیت کن، vendor/minified و kendo theme را دست نزن.

مسیر اسکیل در ریپو: .agents/skills/css-logical-properties-bidi/ — و کپی در personal Agent Store برای پروژه‌های دیگر.

چک‌لیست تست بعد از هر پکیج

  • یک‌بار با html[dir=rtl] و یک‌بار با html[dir=ltr] (سرویس جهت معمولاً هر دو attribute dir و direction را می‌گذارد).
  • مودال، منو، فرم، گرید/جدول اصلی آن پکیج.
  • آیکن‌های «قبلی/بعدی» و drawerها.
  • مطمئن شوید برای Kendo هنوز در RTL کلاس k-rtl اعمال می‌شود.
  • نقشه/کانواس: جابه‌جایی ناخواستهٔ مارکرها را رگرسیون نکنید.
